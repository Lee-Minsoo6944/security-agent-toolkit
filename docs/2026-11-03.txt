1. 왜 add/commit/push로 나누는지
  - git add(선택 및 준비) : 수정된 파일에서 이번 버전에 포함할 파일들만 골라서 
                          준비하는 단계. 작업중인 모든 파일을 무조건 한번에 올리는 것이 아니라, 
                          의미있는 단위별로 나누어 담을 수 있다.
  - git commit(기록 확정) : 준비된 변경사항들을 내 컴퓨터(로컬저장소)에 하나의
                          영구적인 버전(이력)으로 도장 찍듯 확정하는 단계.
  - git push(공유 및 업로드) : 내 PC에 안전하게 기록된 버전들을 원격 저장소로 업로드하여
                            다른 팀원들과 공유하거나 백업하는 단계입니다.

2. commit과 push의 의미
  1) commit의 의미와 메시지를 적는 이유
    - 의미 : 내 PC의 로컬 저장소에 작업물의 상태를 사진처럼 찍어 변경 이력으로 저장
    - 나중에 코드를 다시 봤을 때 수정 시기를 쉽게 알아볼 수 있고, 
      변경 목적을 명확히 이해할 수 있도록 설명하기 위해 commit 메시지를 남긴다.
  2) push의 의미 : 내 PC(로컬저장소)에 쌓아 둔 커밋 기록을 

ㅇ 중첩(nested) → 데이터 구조(리스트, 딕셔너리 등) 내부에 또 다른 동일한 구조가 포함되어 있는 
                 형태를 의미하며, 복잡하고 계층적인 다차원 데이터를 표현할 때 사용합니다.   
ㅇ 딕셔너리 안의 딕셔너리 → 고유한 키(예: 사용자 ID나 IP 등)를 이용해 특정 대상의 세부 속성에 다이렉트로 빠르게 접근해야 할 때 사용합니다. 
                        반면, '리스트 안의 딕셔너리'는 순서가 있는 여러 개의 데이터 목록을 차례대로 순회(반복문)하며 처리할 때 사용합니다.


ㅇ JSON → 프로그램이나 시스템이 서로 다른 프로그래밍 언어(예: Python, Java, JavaScript 등)로 만들어져 있더라도, 
         언어에 구애받지 않고 공통된 텍스트 형식으로 데이터를 안전하게 주고받기 위해 약속한 표준 데이터 교환 형식입니다. 
         사람이 읽기 쉽고 구조가 단순하여 널리 쓰입니다.   
ㅇ 직렬화 → 프로그램이 실행되는 동안 컴퓨터 메모리(RAM) 내부에서 딕셔너리나 객체 형태로 떠돌아다니는 데이터들을, 
           파일로 저장하거나 네트워크를 통해 다른 곳으로 보낼 수 있도록 연속된 문자열(텍스트) 형태로 펼쳐서 변환하는 과정을 의미합니다.
           (반대로 문자열을 다시 메모리 속 객체로 되돌리는 것은 역직렬화/deserialize라고 합니다.)
