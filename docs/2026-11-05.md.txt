1. grep(Global Regular Expression Print)
  - 리눅스 및 유닉스 계열 운영체제에서 파일 내 특정한 문자열이나 
    정규식 패턴을 찾아낼 때 사용하는 핵심 명령어입니다.   
    방대한 텍스트나 서버 로그 파일 속에서 사용자가 원하는 키워드가 포함된 
    줄만 정확하게 골라서 화면에 출력해 주기 때문에, 시스템 관리나 
    보안 담당자가 서버의 이상 징후나 오류, 침해 사고 흔적을 빠르게 추적할 때 
    필수적으로 활용됩니다.

2. 리눅스 로그 검색(grep)
  - 대소문자 구분 없는 에러 탐색: 로그 파일 내에서 대소문자에 구애받지 않고 
                              특정 실패 기록이나 에러 메시지를 누락 없이 찾아낼 때 활용합니다.

  - 하위 디렉터리 일괄 검색: 개별 로그 파일을 일일이 열어볼 필요 없이, 지정한 디렉터리 아래에 있는 
                          모든 파일에서 특정 IP 주소나 사용자 계정의 흔적을 한 번에 재귀적으로 탐색할 수 있습니다.

  - 줄 번호 확인: 검색된 내용이 로그 파일의 정확히 어느 위치에 기록되어 있는지 파악하여 파일 구조를 파악하기 쉽게 만듭니다.

  - 불필요한 로그 제외: 분석에 방해가 되는 일반적인 상태 메시지나 노이즈 행을 제외하고 오직 필요한 정보만 필터링하여 가독성을 높입니다.

  - 전후 상황 파악: 특정 에러 코드가 발견된 지점의 바로 앞뒤 상황을 함께 출력하도록 설정하여, 에러가 
                  발생하기 직전 어떤 이벤트가 있었는지 인과관계를 분석할 수 있습니다.

  - 실시간 필터링: 실시간으로 쌓이는 로그 흐름 중에서 특정한 위험 신호나 경고 키워드만 실시간으로 걸러내어 모니터링 효율을 높일 수 있습니다.

3. 서버 로그 확인 방법
  - 로그 파일 위치 접근: 대부분의 시스템 로그, 인증 기록, 서비스 로그는 시스템 내의 전용 디렉터리(주로 시스템 루트 하위의 로그 전용 경로)에 
                      텍스트 파일 형태로 누적되므로, 해당 경로에 접근하여 파일을 직접 확인할 수 있습니다.

  - 파일 전체 및 페이지별 조회: 로그 파일의 전체 내용을 순차적으로 살펴보거나, 분량이 많을 경우 화면 단위로 
                            끊어서 위아래로 이동하며 확인할 수 있습니다.

  - 실시간 로그 모니터링: 서버가 구동되면서 실시간으로 쌓이는 새로운 이벤트나 에러를 놓치지 않고 화면에 바로바로 출력되도록 하여 
                       현재 상태를 추적할 수 있습니다.

  - 특정 키워드 필터링: 수많은 로그 줄 중에서 특정한 에러 메시지나 실패 기록, 특정 IP 주소 등 필요한 정보만 골라내어 집중적으로 분석할 수 있습니다.

  - 시스템 통합 로그 관리 도구 활용: 개별 파일 형태가 아닌 운영체제 차원에서 관리하는 시스템 저널 도구를 통해 부팅 기록부터 서비스 구동 상태까지 
                                 통합된 로그를 조회할 수 있습니다.

4. 보안담당자들이 grep을 쓰는 이유
  - 보안 담당자가 서버에서 grep을 사용하는 이유는 방대한 서버 로그 파일 속에서 
    보안 위협이나 침해 사고의 흔적을 빠르고 정확하게 찾아내기 위해서입니다.

  - 이상 징후 및 공격 탐지: 시스템 접근 로그나 인증 기록에서 Failed password, Unauthorized, Invalid user 같은 
                         보안 위협 키워드를 필터링하여, 무차별 대입 공격(Brute Force)이나 비정상적인 로그인 시도를 
                         실시간으로 파악할 수 있습니다.

  - 침해 사고 분석(Forensics): 보안 사고 발생 시, 수만 줄이 넘는 로그 속에서 공격자의 특정 IP 주소나 의심스러운 명령어 실행 흔적을 
                             순식간에 추출하여 원인을 분석하고 대응하는 데 필수적이기 때문입니다.
